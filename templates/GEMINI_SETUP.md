# 🔑 Подключение бесплатного Gemini — пошагово

Время: **3 минуты**. Карта не нужна. Лимитов бесплатного тарифа хватит с запасом:
завод делает **2 запроса в день**, а бесплатный Gemini даёт **сотни в сутки**.

---

## Шаг 1. Получить ключ

1. Откройте **[aistudio.google.com/apikey](https://aistudio.google.com/apikey)**.
2. Войдите в свой **Google-аккаунт** (обычный Gmail подойдёт).
3. Примите условия, если появится окно — нажмите **I agree / Продолжить**.
4. Нажмите **Create API key** (или **Get API key**).
5. Если предложит выбрать проект → **Create new project** (название любое, например `libra-factory`).
6. Скопируйте появившийся ключ — он начинается с `AIzaSy…` и имеет длину ~39 символов.

> ⚠️ Ключ показывается полностью. Скопируйте его **сразу** и никуда не публикуйте.

### Проверка ключа в браузере (10 секунд, по желанию)

```
https://generativelanguage.googleapis.com/v1beta/models?key=ВАШ_КЛЮЧ
```

- ✅ Открылся JSON со списком моделей (`"name": "models/gemini-2.5-flash"`) → ключ рабочий.
- ❌ `"error": {"code": 400, "message": "API key not valid"}` → ключ скопирован не полностью.

---

## Шаг 2. Добавить ключ в GitHub

1. Откройте репозиторий → **Settings**.
2. Левое меню: **Secrets and variables** → **Actions**.
3. Вкладка **Secrets** (не Variables!) → кнопка **New repository secret**.
4. Заполните:

| Поле | Значение |
|---|---|
| **Name** | `GEMINI_API_KEY` |
| **Secret** | `AIzaSy…` (вставить целиком, без кавычек и пробелов) |

5. **Add secret**.

> Имя должно быть **ровно** `GEMINI_API_KEY`. При опечатке (`GEMINI_KEY`, `GOOGLE_API_KEY`) завод
> его не увидит и продолжит работать на офлайн-генераторе — без ошибок, но и без ИИ.

---

## Шаг 3. Проверить, что ИИ подключился

Вкладка **Actions** → **Libra Content Factory Autopost** → **Run workflow**:

- `slot`: `auto`
- `dry_run`: **true**

В логе шага `Generate and publish post` появится строка:

```
[2/5] Генерация текста: gemini_free:gemini-2.5-flash → offline_engine (резерв), подпись='@libra_astra'
```

Это значит: ключ найден, первым будет использован Gemini, а офлайн — только как страховка.

В конце появится фактический источник:

```
[OK] Дата: 2026-11-11 | Рубрика: forecast | Источник: gemini_free:gemini-2.5-flash
```

> Если увидите `Источник: offline_engine` и ниже причину `↳ ИИ недоступен…: HTTP 400/401/429` —
> это подскажет, что именно не так (неверный ключ / исчерпан лимит).

## Что изменилось в коде (важно для автономности)

Раньше при ошибке первого провайдера завод сразу уходил в офлайн. Теперь работает **каскад**:

```
LLM_API_KEY → Gemini → Groq → OpenRouter → GitHub Models → офлайн-движок
```

- если Gemini вернёт `429` (дневной лимит) — **автоматически** пробуется Groq (если задан ключ),
  затем остальные, и только потом офлайн;
- **публикация не сорвётся никогда**: при полном отказе всех ИИ пост всё равно выйдет,
  просто текстом офлайн-движка;
- причина отказа попадает в `output/last_post.json` (`fallback_reason`) и в лог.

Проверено локально:

| Сценарий | Результат |
|---|---|
| ключей нет | `offline_engine (ключи ИИ не заданы)` |
| `GEMINI_API_KEY` задан, но неверный | `gemini_free:gemini-2.5-flash → offline_engine (резерв)`, пост сгенерирован (909 символов) |
| `--dry-run` с ключом | карточка и текст генерируются, публикации нет |

## Хотите другую модель?

Бесплатные варианты Gemini (лимиты меняются — актуальные смотрите в AI Studio):

| Модель | Особенность | Как задать |
|---|---|---|
| `gemini-2.5-flash` | по умолчанию, баланс качества/скорости | ничего не делать |
| `gemini-2.5-flash-lite` | выше лимиты, чуть проще текст | Variables → `LLM_MODEL` = `gemini-2.5-flash-lite` |
| `gemini-2.5-pro` | лучшее качество, мало запросов в день | Variables → `GEMINI_MODEL` = `gemini-2.5-pro` |

**Settings → Secrets and variables → Actions → вкладка Variables → New repository variable**
→ **Name:** `GEMINI_MODEL`, **Value:** `gemini-2.5-flash-lite`.

## Если Gemini не подходит

Тот же эффект даёт любой из бесплатных провайдеров — достаточно **одного** ключа:

| Провайдер | Где взять | Имя секрета |
|---|---|---|
| **Groq** (быстро, щедро) | [console.groq.com/keys](https://console.groq.com/keys) | `GROQ_API_KEY` |
| **OpenRouter** (`:free` модели) | [openrouter.ai/keys](https://openrouter.ai/keys) | `OPENROUTER_API_KEY` |

Ключи можно добавить сразу несколько — каскад сам переключится, если один упрётся в лимит.

---

## Частые вопросы

**Нужна ли карта?** Нет. Google AI Studio выдаёт ключ без платёжных данных.

**Что с приватностью?** На бесплатном тарифе Google может использовать запросы для улучшения
моделей. В запросах нет ничего личного — только астродата и промпт канала.

**Не кончится ли лимит?** Заводу нужно 2 запроса в день. Даже урезанные бесплатные лимиты
(десятки–сотни запросов в сутки) покрывают это в разы.

**Что если ключ отзовут?** Публикации не остановятся — включится каскад/офлайн. В логе будет
`↳ ИИ недоступен: HTTP 401`. Тогда получите новый ключ и нажмите **Update** у секрета.
