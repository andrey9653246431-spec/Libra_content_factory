# 🔐 Шаг 3 подробно: Секреты (Secrets) и переменные (Variables)

Это самый ответственный шаг: именно здесь вы «знакомите» контент-завод с вашим Telegram-ботом и каналом.
Ниже — точный путь кликов, форматы значений, способы узнать ID канала и разбор всех ошибок.

> ⏱️ **Быстрый минимум (5 минут):** добавить **2 секрета** — `TG_BOT_TOKEN` и `TG_CHANNEL_ID`. Всё остальное опционально, завод заработает и без них (на офлайн-генераторе).

---

## 0. Где вообще находятся секреты

```
Ваш репозиторий на GitHub
   └── вкладка «Settings»  (верхнее меню репозитория, справа от «Insights»)
         └── раздел «Secrets and variables»  (левое меню, ближе к низу)
               ├── «Actions»
               │     ├── вкладка «Secrets»     ← сюда пароли и токены
               │     └── вкладка «Variables»   ← сюда НЕсекретные настройки
```

Прямая ссылка (подставьте свои значения):

```
https://github.com/USERNAME/REPO/settings/secrets/actions
```

> ⚠️ **Вкладка «Actions» в верхнем меню репозитория — это НЕ то же самое.** Там логи запусков.
> Настройки — только через **Settings → Secrets and variables → Actions**.
>
> ⚠️ Секреты находятся **только у вас** в аккаунте. Если вы загрузили проект как **fork** чужого репозитория — секреты форка не передаются, их нужно добавить в свой форк.

## 1. Правила, которые экономят час отладки

| Правило | Почему важно |
|---|---|
| **Имя секрета — РОВНО как в инструкции**: `TG_BOT_TOKEN` | При опечатке (`TG_TOKEN`, `TELEGRAM_TOKEN`) workflow просто получит пустую строку — ошибки не будет, но пост не уйдёт |
| **Никаких пробелов** в начале/конце значения | `" 1234567890:AAF…"` для Telegram — невалидный токен |
| **Не добавляйте кавычки** | `"@my_channel"` с кавычками Telegram не распознает. Вставляйте `@my_channel` |
| После нажатия **Add secret** значение **больше не посмотреть** | GitHub хранит секреты в зашифрованном виде: доступны только кнопки **Update** (заменить) и **Delete** |
| В логах Actions значения маскируются как `***` | Даже если скрипт случайно напечатает токен — GitHub скроет его. Но чужие токены всё равно не публикуйте |
| Секрет ≠ переменная | В Secrets — только пароли/токены. Названия канала, часовой пояс и режим публикации — во вкладке **Variables** |
| Один секрет — одно значение | Нельзя вписать два токена через запятую |

## 2. Секрет №1 — `TG_BOT_TOKEN` (обязательный)

### 2.1. Создаём бота и получаем токен

1. Откройте Telegram и найдите **@BotFather** (обязательно с синей галочкой — это официальный бот Telegram).
2. Нажмите **Start** (или отправьте `/start`).
3. Отправьте команду:
   ```
   /newbot
   ```
4. Введите **имя бота** — то, что увидят пользователи (можно по-русски, с пробелами). Например: `Весы • Прогноз дня`.
5. Введите **username** — латиница, цифры и `_`, обязательно на `bot` в конце. Пример: `vesy_prognoz_bot`.
   > Если имя занято — BotFather попросит другое.
6. BotFather ответит сообщением:
   ```
   Done! Congratulations on your new bot...
   Use this token to access the HTTP API:
   7891234567:AAF7xQwErTyUiOpAsDfGhJkLzXcVbNm1234
   ```
   Это и есть **токен** вида `<цифры>:<35 символов>`.

### 2.2. Сохраняем токен в GitHub

1. Откройте: **Settings → Secrets and variables → Actions → вкладка Secrets**.
2. Нажмите зелёную кнопку **New repository secret**.
3. Заполните:
   - **Name:** `TG_BOT_TOKEN`
   - **Secret:** вставьте токен целиком (без пробелов и кавычек)
4. Нажмите **Add secret**.

### 2.3. Проверьте токен прямо в браузере (10 секунд)

Скопируйте ссылку и подставьте свой токен:

```
https://api.telegram.org/bot<ВАШ_ТОКЕН>/getMe
```

Пример: `https://api.telegram.org/bot7891234567:AAF7xQw…/getMe`

- ✅ Если видите JSON: `{"ok":true,"result":{"id":7891234567,"is_bot":true,"first_name":"…","username":"vesy_prognoz_bot"}}` — токен рабочий.
- ❌ `{"ok":false,"error_code":401,"description":"Unauthorized"}` — токен скопирован не полностью или отозван. Зайдите в @BotFather → `/mybots` → выберите бота → **API Token** → получите заново.

### 2.4. Если токен «утёк»

@BotFather → `/mybots` → ваш бот → **API Token** → **Revoke current token**. Старый токен перестанет работать, выдайте новый в GitHub через **Update** у секрета.

## 3. Секрет №2 — `TG_CHANNEL_ID` (обязательный)

### 3.1. Сначала добавьте бота в канал администратором

Без этого шага `chat not found` и `bot is not a member` будут выскакивать при любом значении ID.

1. Откройте ваш канал → нажмите на **название канала** вверху.
2. **Управление каналом** (или три точки → *Управление*).
3. **Администраторы** → **Добавить администратора**.
4. Введите username бота (`vesy_prognoz_bot`) и выберите его из списка.
5. Включите как минимум право **«Публикация сообщений»** (Post messages). Остальное можно не давать — это безопаснее.
6. **Сохранить**.

### 3.2. Три способа узнать правильный ID

#### Способ А. Публичный канал (проще всего)

Если у канала есть @username (публичная ссылка вида `t.me/vesy_prognoz`), то ID —
просто этот username с собакой:

```
@vesy_prognoz
```

> Значения `t.me/vesy_prognoz`, `vesy_prognoz`, `https://t.me/vesy_prognoz` — **не подойдут**. Нужно ровно `@vesy_prognoz`.

#### Способ Б. Любой канал (публичный или закрытый) — через @getidsbot

1. Перешлите **любой пост из канала** боту **@getidsbot** (или **@userinfobot**).
2. Он ответит карточкой канала, где будет строка вида:
   ```
   ID: -1001234567890
   ```
3. Скопируйте число **вместе с минусом и префиксом `-100`**.

#### Способ В. Через сам Telegram Bot API (самый надёжный)

1. Убедитесь, что бот уже **администратор канала** (п. 3.1).
2. Опубликуйте (или отредактируйте) любой пост в канале.
3. Откройте в браузере:
   ```
   https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates
   ```
4. В ответе найдите блок `"channel_post": { "chat": { "id": -1001234567890, "title": "Весы • Прогноз дня", "type": "channel" } }`.
5. Число из поля `"id"` — это ваш `TG_CHANNEL_ID`.

> Если вместо JSON приходит `{"ok":false,"error_code":409,"description":"Conflict: can't use getUpdates method while webhook is active"}` — у бота установлен вебхук. Выполните один раз `https://api.telegram.org/bot<ТОКЕН>/deleteWebhook` и повторите.

### 3.3. Форматы: что подходит, а что нет

| Значение | Подходит? | Комментарий |
|---|---|---|
| `@vesy_prognoz` | ✅ | Публичный канал, username |
| `-1001234567890` | ✅ | Любой канал; **обязательно для закрытого** |
| `-1001234567890` без минуса (`1001234567890`) | ❌ | Будет `chat not found` |
| `1234567890` (без `-100`) | ❌ | Telegram примет за ID пользователя → `chat not found` |
| `t.me/vesy_prognoz` или `https://t.me/…` | ❌ | Ссылка вместо ID |
| `-1001234567890_title` / `@` + кириллица | ❌ | Такое в Telegram не существует |

### 3.4. Сохраняем

**Settings → Secrets and variables → Actions → Secrets → New repository secret**

- **Name:** `TG_CHANNEL_ID`
- **Secret:** `@vesy_prognoz` **или** `-1001234567890`

→ **Add secret**.

## 4. Секрет №3 — `TG_ADMIN_ID` (только для режима черновиков)

Нужен, если вы хотите **сначала получать пост себе в личку**, проверять и только потом публиковать.

1. Напишите любое сообщение боту **@userinfobot** — он ответит вашим `Id: 123456789`.
2. Добавьте секрет: **Name** `TG_ADMIN_ID`, **Secret** — ваше числовое ID (без `@` и без минуса).
3. Включите режим: **Settings → Secrets and variables → Actions → Variables → New repository variable**
   - **Name:** `PUBLISH_MODE`
   - **Value:** `draft`
4. **Важно:** напишите вашему боту `/start` в личку, иначе Telegram не даст ему отправить вам сообщение.

Когда захотите вернуться к автопубликации — замените значение `PUBLISH_MODE` на `auto` (или удалите переменную).

## 5. Секреты для ИИ (все опциональны — нужен максимум один)

Генератор текста выбирает провайдера **по приоритету**: `LLM_API_KEY` → `GEMINI_API_KEY` → `GROQ_API_KEY` → `OPENROUTER_API_KEY` → `GITHUB_TOKEN` → **офлайн-движок**.
Завод делает всего **2 запроса в день**, поэтому лимитов бесплатных тарифов хватает с колоссальным запасом.

### 5.1. Google Gemini (рекомендую как основной)

1. Откройте **[aistudio.google.com/apikey](https://aistudio.google.com/apikey)** и войдите в Google-аккаунт.
2. Нажмите **Create API key** → выберите проект (или *Create new project*).
3. Скопируйте ключ вида `AIzaSy…` (39 символов).
4. GitHub → **Secrets** → **New repository secret**:
   - **Name:** `GEMINI_API_KEY`
   - **Secret:** `AIzaSy…`
5. Модель по умолчанию — `gemini-2.5-flash`. При желании задайте во **Variables**: `LLM_MODEL` = `gemini-2.5-flash-lite` (выше лимиты).

> Данные: на бесплатном тарифе Google может использовать ваши запросы для улучшения своих моделей. Для астрологического контента это некритично, но знать стоит.

### 5.2. Groq (быстрый и щедрый бесплатный тариф)

1. [console.groq.com/keys](https://console.groq.com/keys) → войти → **Create API Key**.
2. Ключ вида `gsk_…`.
3. Добавьте секрет **Name:** `GROQ_API_KEY`.
4. Модель по умолчанию — `llama-3.3-70b-versatile`.

### 5.3. OpenRouter (доступ к разным моделям, только `:free`)

1. [openrouter.ai/keys](https://openrouter.ai/keys) → **Create Key**.
2. Ключ вида `sk-or-v1-…`.
3. Добавьте секрет **Name:** `OPENROUTER_API_KEY`.
4. Модель по умолчанию — `meta-llama/llama-3.3-70b-instruct:free`.
   > На бесплатном аккаунте без пополнения лимит ~50 запросов/сутки. Нам нужно 2 — с запасом.

### 5.4. GitHub Models — уже работает, секрет добавлять НЕ нужно

В workflow файле уже прописано:

```yaml
permissions:
  models: read
...
env:
  GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

`GITHUB_TOKEN` GitHub выдаёт автоматически каждому запуску Actions — это не ваш личный токен и добавлять его в Secrets руками не надо.
Завод использует его как последний бесплатный вариант ИИ (модель `openai/gpt-4o-mini`).

> ⚠️ У некоторых аккаунтов доступ к GitHub Models не включён (нужен Copilot/специфические условия) — тогда код просто пойдёт по цепочке ниже и использует **офлайн-генератор**. Это штатное поведение, посты продолжат выходить.
>
> ⚠️ Если у вас есть `GEMINI_API_KEY` или `GROQ_API_KEY`, они имеют приоритет над `GITHUB_TOKEN` — так специально задумано (качество текста выше).

### 5.5. Свой любой OpenAI-совместимый провайдер

Добавьте **секрет** `LLM_API_KEY` и **переменные**:

| Variables | Пример |
|---|---|
| `LLM_BASE_URL` | `https://api.deepseek.com/v1` |
| `LLM_MODEL` | `deepseek-chat` |

## 6. Переменные (Variables) — необязательные настройки

**Settings → Secrets and variables → Actions → вкладка Variables → New repository variable**

| Имя | Значение по умолчанию | Зачем |
|---|---|---|
| `CHANNEL_HANDLE` | `@vesy_prognoz` | Подпись в подвале карточки и в конце поста. Поставьте **ваш** username канала |
| `PUBLISH_MODE` | `auto` | `auto` — сразу в канал; `draft` — черновик вам в личку |
| `TIMEZONE_OFFSET` | `3` | Часовой пояс для определения утреннего/вечернего слота. Москва = `3`, Екатеринбург = `5`, Калининград = `2` |
| `LLM_MODEL` | зависит от провайдера | Заменить модель ИИ |
| `LLM_BASE_URL` | — | Для своего OpenAI-совместимого API |

> Отличие: **Secrets** шифруются и скрываются в логах, **Variables** видны открыто и не годятся для паролей.

## 8. Как проверить, что секреты «подхватились»

### Вариант А. Встроенная диагностика в GitHub (ничего не публикует)

1. Вкладка **Actions** → в левом меню **Check Setup (diagnostics)**.
2. Кнопка **Run workflow** → `test_llm: false` → **Run workflow**.
3. Откройте запуск → шаг **Run diagnostics**. Вы увидите отчёт:

```
[1/5] Telegram-бот
✅ Бот найден: @vesy_prognoz_bot (id 7891234567), токен 789123…1234

[2/5] Канал и права бота
✅ Канал найден: «Весы • Прогноз дня» (id -1001234567890, тип channel)
✅ Бот — администратор канала с правом публикации

[3/5] Режим публикации
✅ Режим публикации: auto (сразу в канал)

[4/5] Генератор текста
✅ Провайдер ИИ: gemini_free, модель gemini-2.5-flash

[5/5] Ресурсы проекта
✅ Pillow установлен — карточки будут генерироваться
==============================================================
✅ ВСЁ ГОТОВО — можно публиковать!
```

С `test_llm: true` скрипт дополнительно сделает один реальный запрос к модели и покажет, рабочий ли ключ.

### Вариант Б. Локально на компьютере

```bash
cd libra-content-factory
pip install -r requirements.txt
export TG_BOT_TOKEN="1234567890:AAF…"      # Windows PowerShell: $env:TG_BOT_TOKEN="…"
export TG_CHANNEL_ID="@vesy_prognoz"
python -m tools.preflight --test-llm
```

> Лучше не «экспортировать» токен в общую оболочку, а заполнить локальный `.env` (он в `.gitignore` и не попадёт в репозиторий) — `preflight` читает его автоматически.

## 9. Разбор ошибок по тексту сообщения

| Сообщение | Что произошло | Как исправить |
|---|---|---|
| `❌ TG_BOT_TOKEN не задан` | Секрет с таким именем не создан или имя с опечаткой | Проверьте имя ровно `TG_BOT_TOKEN` на вкладке Secrets |
| `Telegram отклонил — Unauthorized (401)` | Токен неполный / отозван / от другого бота | Скопируйте заново из @BotFather → `/mybots` → API Token → **Update** секрета |
| `❌ TG_CHANNEL_ID не задан` | Секрет не создан | Добавьте `TG_CHANNEL_ID` |
| `chat not found` | Бот не в канале **или** ID в неверном формате | 1) Добавьте бота админом; 2) для закрытого канала — числовой `-100…`; 3) проверьте минус и префикс |
| `bot is not a member of the channel chat` | Бот удалён из канала или не админ | «Добавить администратора» заново |
| `not enough rights to send photos to the chat` | У бота нет права «Публикация сообщений» | Канал → Администраторы → ваш бот → включить **Post messages** |
| `Forbidden: bot was blocked by the user` (в режиме draft) | Вы не нажали `/start` у своего бота | Откройте бота в Telegram → **Start** |
| `Conflict: can't use getUpdates … webhook is active` | У бота установлен вебхук | Вызовите в браузере `…/bot<ТОКЕН>/deleteWebhook` |
| Секрет есть, но в логах пусто (`env` не видит) | Секрет добавлен как **Environment secret** в другом окружении | Добавьте его на вкладке **Repository secrets** |
| `Провайдер ИИ: github_models` и текст с ошибкой в логе | GitHub Models недоступен аккаунту | Добавьте `GEMINI_API_KEY` или ничего не делайте — сработает офлайн-генератор |
| `429 RESOURCE_EXHAUSTED` | Исчерпан дневной лимит бесплатного тарифа | Завод автоматически уйдёт в офлайн-режим; лимит обновится на следующий день |

## 10. Безопасность — коротко и по делу

1. **Репозиторий держите Private.** Публичный репозиторий с секретами всё равно их не раскроет, но код и история публикаций — ваши внутренние данные.
2. **Никогда не коммитьте `.env`.** Файл уже в `.gitignore`; если случайно загрузили — удалите его из репозитория и отзовите токены.
3. **Права бота — минимальные.** Только «Публикация сообщений». Не давайте «Добавление администраторов» и «Удаление сообщений».
4. **Дайте боту отдельное имя** (`vesy_prognoz_bot`), не используйте одного бота в разных проектах.
5. **Секреты не передаются в pull request'ы из форков** — это защита GitHub, не баг.
6. **Утечка токена** → @BotFather → `/revoke` → новый токен → **Update** секрета. Старый сразу перестанет работать.
