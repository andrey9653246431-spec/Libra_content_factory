# 🤖 Автоматический режим: как включить и как проверить

## Короткий ответ

Расписание **уже встроено** в `.github/workflows/autopost.yml`:

```yaml
on:
  schedule:
    - cron: "30 5 * * *"    # 08:30 МСК — астропрогноз дня
    - cron: "0 16 * * *"    # 19:00 МСК — Таро / Любовь / Венера / Неделя
```

После того как один ручной запуск прошёл успешно (у вас это уже было — запуск №15),
**больше ничего делать не нужно**: GitHub сам запускает workflow каждый день.

Осталось закрыть три вещи, которые могут помешать (см. ниже).

---

## 1. Обновить `autopost.yml` — иначе подпись останется `@vesy_prognoz`

В репозитории всё ещё лежит старая версия. Замените файл:

`https://github.com/andrey9653246431-spec/Libra_content_factory/blob/main/.github/workflows/autopost.yml`
→ ✏️ **Edit this file** → **Ctrl+A** → **Delete** → вставить `/home/user/upload-files/autopost.yml` → **Commit changes**

> Правка workflow вызовет автозапуск в режиме `dry_run` — пост не уйдёт, это нормально.

---

## 2. Убедиться, что Actions включены и workflow не отключён

**Settings → Actions → General** → раздел *Actions permissions*:

- должно быть выбрано **Allow all actions and reusable workflows** (или как минимум разрешены actions/checkout, setup-python, upload-artifact);
- ниже, в *Workflow permissions*, оставьте **Read and write permissions** (нужно для коммита `data/history.json`).

Если workflow когда-то отключали вручную, в **Actions → Libra Content Factory Autopost** сверху
появится кнопка **Enable workflow** — нажмите её.

---

## 3. Защита от «60 дней без активности» (для публичных репозиториев)

GitHub отключает `schedule` в **публичных** репозиториях после 60 дней без коммитов.
Ваш репозиторий публичный. Решение — файл **`.github/workflows/keepalive.yml`**
(лежит в `/home/user/upload-files/keepalive.yml`):

```yaml
on:
  schedule:
    - cron: "17 4 1 * *"   # 1-го числа каждого месяца
```

Он раз в месяц делает микро-коммит `.github/keepalive.txt` — расписание никогда не отключается.

**Как добавить:** **Add file → Create new file** → имя ровно
`.github/workflows/keepalive.yml` → вставить содержимое → **Commit changes**.

> Альтернатива: перевести репозиторий в **Private**. Там лимит 2000 бесплатных минут Actions
> в месяц, а «Весы» тратят ~1 минуту в день (~30 минут/мес) — с огромным запасом.
> Тогда правило 60 дней не действует.

## Что произойдёт дальше (ожидаемый график)

| Когда | Что |
|---|---|
| Сегодня **19:00 МСК** (16:00 UTC) | Первый автоматический пост: вечерняя рубрика по дню недели |
| Завтра **08:30 МСК** (05:30 UTC) | Утренний астропрогноз дня |
| Каждый день | 2 поста, карточки генерируются заново с реальной фазой Луны |
| После каждой публикации | Бот коммитит `data/history.json` — карты Таро и знаки не повторяются |

## Как проверить автоматику, ничего не нажимая

1. Откройте **Actions** — у запусков в колонке события будет написано **`Schedule`**
   (у ручных — `workflow_dispatch`). Появление записи `Schedule` = автоматика работает.
2. Или проверьте сам канал: пост в 08:30 / 19:00 МСК без вашего участия.
3. Логи запусков хранятся 90 дней, артефакты с карточками — 7 дней.

## Важные ограничения GitHub (чтобы не было сюрпризов)

| Ограничение | Что делать |
|---|---|
| **Задержка cron 5–20 минут** | Нормально для бесплатного GitHub. Пост может выйти в 08:40 вместо 08:30 |
| **Cron идёт по UTC** | В файле уже пересчитано: `30 5` → 08:30 МСК, `0 16` → 19:00 МСК |
| **60 дней простоя** → отключение schedule | `keepalive.yml` (выше) или Private-репозиторий |
| **Секреты недоступны в fork/PR** | Не актуально, репозиторий ваш |
| **Лимит 2000 минут** (Private) | Тратится ~1 мин/запуск, ~30 мин/мес — безопасно |
| **Публичный репозиторий = виден код** | Если это важно — Settings → General → **Change visibility → Private** |

## Хотите изменить время или количество постов?

Откройте `.github/workflows/autopost.yml` и поправьте `cron` (время в UTC, МСК = UTC+3):

```yaml
- cron: "30 5 * * *"    # 08:30 МСК — утро
- cron: "0 16 * * *"    # 19:00 МСК — вечер
```

- **Один пост в день** → удалите вечернюю строку.
- **Три поста** → добавьте `- cron: "0 9 * * *"` (12:00 МСК).
- **Другое время** → вычтите 3 часа: 10:00 МСК = `0 7 * * *`.
