# ✅ Мои действия по шагам

Ситуация: шаги 1–6 зелёные, шаг 7 (`Generate and publish post`) падает за 1 секунду.
Это значит: код запустился, дошёл до публикации и получил отказ. Точную причину скрывает старая версия `src/main.py`.

Ниже — 5 действий, ~10 минут. Делать по порядку.

## Действие 3. Проверить секреты (3 минуты) ← **скорее всего причина здесь**

Откройте: **Settings → Secrets and variables → Actions**

### 3.1. Вкладка «Secrets» — должны быть ровно эти имена

| Имя | Значение |
|---|---|
| `TG_BOT_TOKEN` | токен вида `7891234567:AAF7xQwErTy…` |
| `TG_CHANNEL_ID` | `@ваш_канал` (публичный) или `-1001234567890` (любой) |

Проверьте:
- [ ] секреты созданы именно во вкладке **Secrets**, а не **Variables**;
- [ ] имена совпадают посимвольно (не `TG_TOKEN`, не `TELEGRAM_BOT_TOKEN`);
- [ ] в значении нет кавычек и пробелов: `@channel`, а не `"@channel"`;
- [ ] для закрытого канала указан числовой id `-100…`, а не `@username`.

Если `TG_CHANNEL_ID` не хочется возиться — можно вместо него:
**Variables** → `CHANNEL_HANDLE` = `@ваш_канал` (код подставит его сам).

### 3.2. Проверка токена в браузере (10 секунд)

Откройте (подставьте свой токен):

```
https://api.telegram.org/bot<ВАШ_ТОКЕН>/getMe
```

- ✅ `{"ok":true,"result":{"username":"…_bot",…}}` → токен рабочий.
- ❌ `{"ok":false,"error_code":401,"description":"Unauthorized"}` → токен неполный/отозван:
  @BotFather → `/mybots` → ваш бот → **API Token** → новый → **Update** у секрета.

## Действие 4. Проверить, что бот — админ канала (1 минута)

1. Откройте свой канал в Telegram → нажмите на **название канала**.
2. **Управление каналом → Администраторы → Добавить администратора**.
3. Введите username бота, выберите его.
4. Включите **«Публикация сообщений»** (Post messages) → **Сохранить**.

Без этого Telegram отвечает `403 bot is not a member` или `400 chat not found`.

## Действие 5. Два запуска (5 минут)

Вкладка **Actions → Libra Content Factory Autopost → Run workflow**.

### Запуск A — проверка без публикации

- `slot`: `auto`
- `dry_run`: **true** (галочка/true)
- **Run workflow**

Должно быть зелёным. В логе шага `Generate and publish post`:

```
::notice::Запуск: slot=morning dry_run=True token_set=True channel_set=True
[1/5] Расчёт астроданых: …
[2/5] Генерация текста: провайдер=auto
[3/5] Рендер карточки: forecast
[OK] Опубликовано в Telegram: False
```

> Если запуск A **зелёный** — код и карточки в порядке, проблема ровно в секретах/правах → вернитесь к Действиям 3–4.
> Если в `::notice::` будет `token_set=False` — секрет `TG_BOT_TOKEN` не подхватывается (не создан или лежит в Variables).

### Запуск B — реальная публикация

- `slot`: `auto`
- `dry_run`: **false**
- **Run workflow**

Успех выглядит так:

```
[4/5] Публикация: channel='@ваш_канал', mode='auto', token=задан, caption_len=622
[OK] Опубликовано в Telegram: True
```

Пост с карточкой появится в канале.

## Если снова упадёт — пришлите **одну строку**

В шаге `Generate and publish post` найдите блок:

```
❌ ГЕНЕРАЦИЯ/ПУБЛИКАЦИЯ НЕ УДАЛАСЬ
   RuntimeError: Telegram API error (<код>): <описание>
```

Скопируйте эту строку целиком. Расшифровка:

| Строка | Причина | Действие |
|---|---|---|
| `401: Unauthorized` | токен неверный/отозван | Действие 3.2 |
| `400: chat not found` | бот не в канале или неверный ID | Действия 3.1 + 4 |
| `403: bot is not a member` | бот не админ | Действие 4 |
| `403: not enough rights to send photos` | нет права «Публикация сообщений» | Действие 4, включить галочку |
| `Не заданы секреты: …` | секрет не подхватился | Действие 3.1 |

```

```

Это быстрее, чем читать логи падающих публикаций.
