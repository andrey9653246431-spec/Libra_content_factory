# 🖱️ Почему нет кнопки «Run workflow» — и что нажать

## Сначала: где вообще эта кнопка

Кнопка **Run workflow** есть **только внутри страницы конкретного workflow**.
На общем списке «All workflows» её нет — это самая частая причина «не нашёл».

Правильный путь:

```
1. Верхнее меню репозитория → вкладка «Actions»
2. СЛЕВА в списке workflows нажмите на название:
      • «Check Setup (diagnostics)»   ← проверка секретов
      • «Libra Content Factory Autopost» ← публикация постов
3. Справа сверху появится синяя кнопка «Run workflow» с выпадающим списком
```

Схема:

```
┌──────────────────────────────────────────────────────────────┐
│  Actions  │ All workflows                                      │
├───────────────────────┬──────────────────────────────────────┤
│ Workflows             │  Check Setup (diagnostics)           │
│  ▸ All workflows      │  ┌────────────────────┐              │
│  ▸ Check Setup        │  │ ▸ Run workflow  ▼  │  ← ВОТ ОНА   │
│  ▸ Libra Content…     │  └────────────────────┘              │
└───────────────────────┴──────────────────────────────────────┤
```

> На телефоне в приложении GitHub вкладка Actions может быть урезана — **откройте github.com в браузере** (или «Версия для компьютера»).

## Если кнопки всё равно нет: 5 причин по порядку

### Причина 1. Открыт список «All workflows», а не сам workflow

**Как проверить:** слева в списке названия выделено «All workflows»?

**Решение:** кликните по названию workflow → кнопка появится справа.

---

### Причина 2. Папка `.github/workflows/` не попала в репозиторий

**Как проверить** — откройте ссылку, подставив свой логин и репозиторий:

```
https://github.com/ВАШ_ЛОГИН/ВАШ_РЕПО/blob/main/.github/workflows/autopost.yml
https://github.com/ВАШ_ЛОГИН/ВАШ_РЕПО/blob/main/.github/workflows/check-setup.yml
```

- ✅ открывается YAML-текст → файлы на месте, причина в другом.
- ❌ «404 — This is not the web page you are looking for» → файлов нет, нужно создать.

**Решение (2 минуты, прямо в браузере):**

1. В репозитории: **Add file → Create new file**.
2. В поле имени введите ровно:
   ```
   .github/workflows/check-setup.yml
   ```
   (как только наберёте `/`, GitHub сам создаст папки)
3. Вставьте содержимое файла из проекта (можно открыть локально в Блокноте) → **Commit changes**.
4. Повторите то же для `.github/workflows/autopost.yml`.
5. Обновите вкладку **Actions** (F5).

---

### Причина 3. Workflow лежит не в основной ветке

GitHub показывает кнопку **Run workflow** только для файлов, которые есть в **ветке по умолчанию** (обычно `main`).

**Как проверить:** в репозитории слева сверху над списком файлов указана ветка (например `main`). Файл `.github/workflows/…` должен существовать именно в ней.

**Решение:** если загружали через веб-интерфейс, убедитесь, что коммит сделан в `main` (в поле «Commit changes» внизу выбирается ветка). Если файл только в другой ветке — сделайте Pull Request и слейте в `main`.

---

### Причина 4. В файле ошибка YAML

**Как проверить:** на вкладке **Actions** сверху появляется красная плашка:
*«Some workflows contain errors. Fix them to enable running your workflows.»* → нажмите **View workflows with errors**.

Типичные причины: лишние/недостающие отступы (пробелы, не табы), кириллица в качестве ключа, `on:` с неверным отступом.

**Решение:** скопируйте содержимое файлов заново из проекта — они проверены. Затем перезапишите файл в GitHub (**Edit this file → выделить всё → вставить → Commit changes**).

---

### Причина 5. Actions выключены для аккаунта/репозитория

**Как проверить:** **Settings → Actions → General**. Если видите надпись
*«GitHub Actions is currently disabled for this repository»* — Actions отключены.

Также проверьте **Settings → Billing and plans**: если статус **«Usage blocked»** и не привязан способ оплаты, запуски не стартуют даже в пределах бесплатных 2000 минут.
Обходной путь без оплаты — сделать репозиторий **Public** (**Settings → General → Danger Zone → Change visibility → Public**): Actions для публичных репозиториев бесплатны и без минутных лимитов.

## Что я уже поменял в проекте, чтобы кнопка точно появилась

1. **Оба workflow теперь срабатывают ещё и на `push`** при изменении самого файла workflow:
   - `check-setup.yml` — при правке `check-setup.yml` или `tools/preflight.py`;
   - `autopost.yml` — при правке `autopost.yml` (и этот автозапуск **никогда не публикует пост**, работает как `dry_run`).

   Поэтому GitHub зарегистрирует workflow сразу после коммита, и кнопка появится без ручных действий.
2. **В диагностике добавлен шаг с понятным именем** — `Run diagnostics`, его видно в логе запуска.

> Если вы уже загрузили проект до этого изменения — просто перезалейте два файла:
> `.github/workflows/autopost.yml` и `.github/workflows/check-setup.yml` (и `tools/preflight.py`).

## Проверка без GitHub вообще (если кнопка так и не появилась)

Секреты можно проверить локально за 30 секунд:

```bash
cd libra-content-factory
pip install -r requirements.txt
python -m tools.preflight --test-llm
```

Скрипт читает `.env` из папки проекта. Заполните `.env` (он в `.gitignore` и не уйдёт в репозиторий):

```ini
TG_BOT_TOKEN=1234567890:AAF…
TG_CHANNEL_ID=@ваш_канал
GEMINI_API_KEY=AIzaSy…
```

Ожидаемый результат:

```
[1/5] Telegram-бот
✅ Бот найден: @vesy_prognoz_bot (id 7891234567), токен 789123…1234
[2/5] Канал и права бота
✅ Канал найден: «Весы • Прогноз дня» (id -1001234567890, тип channel)
✅ Бот — администратор канала с правом публикации
...
✅ ВСЁ ГОТОВО — можно публиковать!
```

## Минимальный чек-лист

- [ ] Вкладка **Actions** → слева кликнуть название workflow (не «All workflows»)
- [ ] Файлы `.github/workflows/*.yml` открываются по прямой ссылке в ветке `main`
- [ ] На странице Actions нет красной плашки об ошибках YAML
- [ ] **Settings → Actions → General** — Actions разрешены
- [ ] Если репозиторий Private и статус «Usage blocked» — сделать Public либо добавить способ оплаты
- [ ] Перезалить обновлённые `.github/workflows/` из проекта
