# 🌍 Gemini не работает из России — что делать

## Что произошло

Google AI Studio и Gemini API **не поддерживаются в России** — этой страны нет в официальном
списке доступных регионов. Поэтому вместо страницы с ключами открывается
*«Available regions for Google AI Studio and Gemini API»*.

Это не ошибка вашей настройки и не проблема проекта. Регион определяется по IP,
и обойти это «настройками» нельзя.

**Важно:** контент-завод от этого **не остановился**. Он уже публикует посты на встроенном
офлайн-генераторе: реальная астрология, карточки, антиповтор — всё работает. ИИ влияет только
на «живость» формулировок.

---

## Вариант 1 ⭐ Рекомендую: Groq (без карты, работает из РФ)

Groq — бесплатный хостинг открытых моделей (Llama 3.3 70B и др.). Региональных блокировок
для России нет, ключ выдаётся мгновенно.

1. Откройте **[console.groq.com/keys](https://console.groq.com/keys)**.
2. Войдите через **Google / GitHub / email** (одно нажатие).
3. Нажмите **Create API Key** → имя любое (`libra`) → **Submit**.
4. Скопируйте ключ вида `gsk_…` (он показывается один раз).
5. В GitHub: **Settings → Secrets and variables → Actions → Secrets → New repository secret**

| Поле | Значение |
|---|---|
| **Name** | `GROQ_API_KEY` |
| **Secret** | `gsk_…` |

6. Проверка: **Actions → Libra Content Factory Autopost → Run workflow**, `dry_run: true`.
   В логе: `[2/5] Генерация текста: groq_free:llama-3.3-70b-versatile → …`
   и `Источник: groq_free:llama-3.3-70b-versatile`.

> Бесплатный лимит Groq — десятки запросов в минуту и тысячи в день. Заводу нужно **2 запроса в сутки**.

## Вариант 2: OpenRouter с бесплатными моделями

1. **[openrouter.ai/keys](https://openrouter.ai/keys)** → **Create Key** → скопируйте `sk-or-v1-…`.
2. В GitHub секрет: **Name** `OPENROUTER_API_KEY`.
3. Модель по умолчанию — `meta-llama/llama-3.3-70b-instruct:free`.

> Без пополнения баланса лимит ~50 запросов в сутки — для 2 постов более чем достаточно.
> OpenRouter может требовать вход через Google-аккаунт; из РФ обычно доступен.

---

## Вариант 3: GitHub Models (уже встроен, ничего не делать)

В workflow уже стоит `permissions: models: read` и передаётся `GITHUB_TOKEN`, который GitHub
выдаёт автоматически. Если доступ к GitHub Models для вашего аккаунта открыт — завод использует
его **последним в каскаде** (модель `openai/gpt-4o-mini`) без всяких ключей.

> У части аккаунтов доступ не включён — тогда просто сработает офлайн-движок. Это штатно.

---

## Вариант 4: свой OpenAI-совместимый провайдер

Подходит любой сервис с OpenAI-совместимым API и ключом (в том числе российские:
YandexGPT через прокси-совместимые шлюзы, GigaChat через адаптеры, локальный Ollama на ПК и т.п.).

В GitHub:

| Тип | Имя | Значение |
|---|---|---|
| Secret | `LLM_API_KEY` | ваш ключ |
| Variable | `LLM_BASE_URL` | например `https://api.deepseek.com/v1` |
| Variable | `LLM_MODEL` | например `deepseek-chat` |

---

## Что важно: каскад провайдеров (уже в коде)

```
LLM_API_KEY → Groq → Gemini → OpenRouter → GitHub Models → офлайн-движок
```

- Если у первого провайдера закончился лимит (`HTTP 429`) — автоматически пробуется следующий.
- Если все недоступны — пост всё равно выйдет, текстом офлайн-движка.
- Причина отказа пишется в лог: `↳ ИИ недоступен, использован офлайн-движок: …`

Можно задать **несколько ключей сразу** (Groq + OpenRouter) — это максимальная надёжность:
если один упрётся в лимит, второй подхватит без вашего участия.

## Офлайн-режим тоже улучшен

Даже без ИИ тексты больше не однотипны:

- добавлены **5 вступлений и 2–3 концовки** на каждую рубрику, выбираются детерминированно по дате;
- итого только для прогноза дня — комбинации «вступление × консеология × совет по делам × совет по любви × CTA»
  дают десятки вариантов, не повторяющихся день ото дня;
- добавлена **авто-подгонка длины**: пост гарантированно укладывается в лимит подписи
  Telegram 1024 символа (проверено на 28 датах: максимум 1000).
